# HolyLife (Faith Pathway) — 프로젝트 개요서

> 문서 버전: 1.0 · 최종 갱신: 2026-11-11
> 대상 독자: 기획·개발·운영 담당자, 신규 합류자

---

## 1. 프로젝트 목적

개인이 설교·QT(큐티)·P.B.S(개인성경공부)·독서노트를 한곳에서 기록·관리하고,
성경 본문(개역개정/새번역/NIV)을 바로 조회하며 묵상할 수 있는 **개인 신앙 기록 플랫폼**입니다.

- 웹 기반(PC/태블릿/모바일 반응형)
- 매일 QT 본문을 자동 수집하여 "오늘의 QT"로 제공
- 관리자 기능(사용자·메뉴·권한·공통코드) 포함

---

## 2. 범위

### 포함 (In Scope)
| 영역 | 내용 |
|------|------|
| 인증 | 이메일/비밀번호 로그인, JWT, 역할 기반 접근 제어 |
| 설교 | 목록·등록·수정·삭제, 설교자, 성경 본문 연동, 공개 범위 |
| QT | 목록·등록·수정·삭제, 크롤링 본문 불러오기, 3개 역본 탭, 공개 여부 |
| P.B.S | 폴더 트리 + 페이지(Confluence형), 자동저장, 배포, 드래그&드롭 |
| 독서노트 | 목록·등록·수정·삭제 (목차/요약/느낀점) |
| 성경 | 66권 3역본 본문 조회 (장·절 범위) |
| 대시보드 | 통계, 오늘의 QT, 월간 작성 현황, 최근 콘텐츠 |
| 시스템 관리 | 사용자, 역할, 메뉴, 권한, 공통코드 |
| 배치 | QT 매일 자동 수집(04:00 / 04:05), 수동 실행 API |

### 제외 (Out of Scope)
- 다중 사용자 협업 편집(동시 편집)
- 모바일 네이티브 앱 (현재 웹 전용, Capacitor 방식 검토 단계)
- 외부 SNS 로그인 (Google/Kakao/Naver)
- 유료 결제·구독
- 타 언어 지원 (한국어 단일)

## 3. 사용자 및 역할

| 역할 | 코드 | 설명 | 주요 접근 |
|------|------|------|-----------|
| 시스템 관리자 | `SYS_ADMIN` | 전체 관리 | 모든 화면 + 시스템 관리 메뉴 |
| 개발/운영 | `AGENT_DEV` | 콘텐츠 개발·관리 | 콘텐츠 + 일부 관리 |
| 일반 사용자 | `GENERAL` | 콘텐츠 작성 | 설교/QT/P.B.S/독서/마이페이지 |

---

## 4. 시스템 구성

```
[브라우저]
   │ HTTP :38080
   ▼
[Nginx]  ─ 정적 파일(/opt/holylife/holylifeView)
   │       ─ /api, /uploads, /swagger-ui 프록시
   ▼ HTTP :38081
[Spring Boot 4.0]  ─ JWT 인증, REST API
   │                ─ Spring Batch (QT 수집 스케줄러)
   ▼ JDBC :3306
[MariaDB 10.11]  ─ holylife 스키마
```

| 구성 요소 | 기술 | 포트 |
|-----------|------|------|
| 웹 서버 | Nginx 1.24 | 38080 |
| 백엔드 | Spring Boot 4.0 / Java 17 / MyBatis 4.0.1 | 38081 |
| DB | MariaDB 10.11 | 3306 (로컬) |
| 프론트 | Vue 3.5 / TypeScript / Vite 6 | (빌드 후 Nginx 서빙) |

---

## 5. 성공 기준

- 로그인 후 4개 콘텐츠(설교/QT/P.B.S/독서)를 **작성·조회·수정**할 수 있다
- QT가 **매일 04:00/04:05 자동 수집**되고, 실패 시 수동 재실행이 가능하다
- 성경 본문이 **장·절 범위로 정확히 조회**된다 (3역본)
- 관리자가 **사용자·메뉴·권한**을 화면에서 관리할 수 있다
- PC/태블릿/모바일에서 레이아웃이 깨지지 않는다
- 배치 실행 이력이 DB에 영속되어 추적 가능하다

## 6. 주요 제약 및 결정 사항

| 항목 | 결정 | 사유 |
|------|------|------|
| QT 수집 | Python 스크립트가 아닌 **Spring Batch** | 스케줄·이력·재실행을 애플리케이션 내에서 관리 |
| P.B.S 구조 | 목록/등록 CRUD → **폴더+페이지(Confluence형)** | 문서를 계층적으로 축적하는 사용 패턴 |
| 본문 편집 | Tiptap 리치 에디터 공통 사용 | 4개 콘텐츠 영역의 편집 UX 통일 |
| 인증 | JWT 24시간, localStorage | SPA 단순화 (리프레시 토큰 미도입) |
| 배포 | Nginx + systemd + watchdog | 단일 서버 운영, Docker 미사용 |
| 앱 | 웹 유지 + Capacitor 검토 | 코드 재사용, 사내망 HTTP 제약 |
